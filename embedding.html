🧭 词向量：把词变成能算数的东西

计算机不认识"国王""女人"，只认识数字。词向量做的事情，就是把每个词变成一串数字，而且让意思相近的词，数字也相近——近到可以用加减法推理语义。

①直觉：从"符号"到"坐标"

最早的做法是 One-Hot：词表里第 3 个词就编码成 [0,0,1,0,0,...]。问题是——任意两个不同的词，距离都一样远，"猫"和"狗"的距离跟"猫"和"民主"的距离完全相同。这完全丢掉了语义。

一句话直觉： 词向量把每个词放到一个高维空间里的一个点上。意思相近的词，点挨得近；语义关系（比如"性别"、"国别"）会变成空间里固定的方向。于是"国王 − 男人 + 女人"才会算出来等于"女王"。

分布式假设：词义藏在它的邻居里

1957 年语言学家 Firth 说过一句名言："You shall know a word by the company it keeps."（看一个词跟谁玩，就知道它是什么人。）"银行"总跟"存款、利率、贷款"一起出现，"河岸"总跟"河流、水流、泥沙"一起出现——上下文分布不同，词义就不同。这就是所有词向量方法的理论根基。

基于计数

统计共现次数，构建共现矩阵，再做降维。代表：LSA、GloVe。稳定但矩阵巨大。

基于预测

用神经网络预测上下文，把权重当向量。代表：Word2Vec。快、效果好。

上下文相关

同一个词在不同句子里给不同向量。代表：ELMo、BERT。解决一词多义。

②数学：目标函数到底在优化什么

共现矩阵与相似度

先统计词与词在同一窗口里共现的次数，得到矩阵 \\( M \in \mathbb{R}^{|V|\times|V|} \\)。衡量两个词向量相似度最常用余弦相似度：

\\( \text{sim}(u,v)=\cos\theta=\dfrac{u\cdot v}{\|u\|\,\|v\|}=\dfrac{\sum_i u_i v_i}{\sqrt{\sum_i u_i^2}\sqrt{\sum_i v_i^2}} \\)

它只看方向、不看长度——因为词频高低不该影响"意思像不像"。

CBOW 与 Skip-gram

CBOW：拿上下文预测中心词（小上下文窗口，更快）。Skip-gram：拿中心词预测上下文（对低频词更好）。以 CBOW 为例，目标是让"给定上下文预测中心词"的条件概率最大：

\\( \mathcal{L}=-\dfrac{1}{T}\sum_{t=1}^{T}\log p(w_t \mid w_{t-m},\dots,w_{t+m}) \\) \\( p(w_t\mid \text{ctx})=\dfrac{\exp(u_{w_t}^{\top} h)}{\sum_{w'=1}^{|V|}\exp(u_{w'}^{\top} h)} \\)

其中 \\( h \\) 是上下文向量的平均。分母要对整个词表求和——词表几万到几十万，这一步太慢，所以有了下面的加速。

负采样：把"几十万分类"变成"一个是非题"

不预测"到底是哪个词"，只判断"真实搭配 vs 随机乱配"。这就是从多分类变成二分类，核心损失：

\\( \mathcal{L}=-\log\sigma(u_o^{\top}h)-\sum_{k=1}^{K}\mathbb{E}_{w_k\sim P_n(w)}\big[\log\sigma(-u_{w_k}^{\top}h)\big] \\)
为什么有效？ 分母那个巨大求和没了，每次只抽 K 个（通常 5–15 个）负样本。训练速度提升几十倍，效果几乎不损失。这是 word2vec 能流行的关键工程技巧。

③代码：从零实现 Skip-gram + 负采样

import torch, torch.nn as nn, torch.nn.functional as F

class SkipGramNeg(nn.Module):
    def __init__(self, vocab_size, dim=128):
        super().__init__()
        # 每个词两套向量：作为中心词(in) 和 作为上下文(out)
        self.in_emb  = nn.Embedding(vocab_size, dim)
        self.out_emb = nn.Embedding(vocab_size, dim)
        # 初始化为小随机值，避免一开始就“太自信”
        nn.init.uniform_(self.in_emb.weight, -0.5/dim, 0.5/dim)
        nn.init.zeros_(self.out_emb.weight)

    def forward(self, center, context, negatives):
        # center: [B]   context: [B]   negatives: [B, K]
        v  = self.in_emb(center)                       # [B, D] 中心词向量
        u  = self.out_emb(context)                     # [B, D] 正样本上下文向量
        u_neg = self.out_emb(negatives)                # [B, K, D] 负样本

        pos = (v * u).sum(-1)                       # 正样本得分 [B]
        neg = torch.bmm(u_neg, v.unsqueeze(-1)).squeeze(-1)  # [B, K]

        # 正样本越像越好，负样本越不像越好（logsigmoid 数值更稳）
        loss = -F.logsigmoid(pos).mean() - F.logsigmoid(-neg).mean()
        return loss

# 训练循环示意
model = SkipGramNeg(vocab_size=30000, dim=128)
opt = torch.optim.Adam(model.parameters(), lr=2e-3)
for center, context in data_loader:          # 滑窗切出的正样本对
    negatives = torch.randint(0, 30000, (center.size(0), 10))  # K=10
    loss = model(center, context, negatives)
    opt.zero_grad(); loss.backward(); opt.step()
💡 关键点：正样本来自真实语料的滑窗，负样本从词表里随机抽。logsigmoid 而不是 log(sigmoid(x))，是因为后者在 x 很负时会下溢成 -inf。

④实战：怎么选、怎么用、坑在哪

维度选多少？

经验值：几十万词表用 100–300 维，小语料 50–100 维就够。维度越高表达力越强，但更容易过拟合、更耗显存。别盲目上 768/1024，那通常是给 Transformer 用的。

GloVe 和 Word2Vec 谁好？

实践中差别不大，GloVe 用全局共现统计，Word2Vec 用局部滑窗预测。选哪个主要看训练资源和语料规模。真正质的飞跃是 ELMo/BERT 的上下文相关向量。

典型用途

语义检索（把 query 和文档都转成向量做近邻搜索）、文本聚类、推荐（item2vec）、冷启动特征。在 LLM 时代，embedding 仍是 RAG 检索的第一块基石。

常见坑

① 静态词向量无法处理一词多义（"苹果"手机 vs 水果）；② 未登录词只能给 UNK 或按子词拼；③ 类比运算在很多语料上并不稳定，别当成万能定律；④ 训练语料有偏，向量里会隐含偏见。
