⚡KV Cache 为什么能让大模型加速

大模型生成时每一步都要重新算前面所有 token 的 K 和 V——这其实是重复计算。KV Cache 把之前算好的 K/V 存起来复用，生成第 N 个 token 的时间大幅下降。下面对比两种方式的计算量。

⚡ 无 Cache vs 有 KV Cache

10 tokens
💡 直觉：因果掩码让第 t 个 token 只能看到 1..t，所以它的 Q 只和前 t 个 K/V 算注意力。前面 t-1 个 K/V 在上一步已经算过、完全没变——直接缓存下来就不用重算。生成 N 个 token 的复杂度从 O(N²) 降到 O(N)（prefill O(N²) 只做一次，decode 阶段每步 O(N)）。

⚠️ 代价：要存 K 和 V，层数×头数×维度×序列长度，长上下文时显存占用明显。这就是为什么 128K 上下文模型需要大量显存。
