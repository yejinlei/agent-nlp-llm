01

👦 记忆力超群的"考试型选手"

难度 ★★ 过拟合 监督微调 / 分类头
病人症状 一个文本分类模型，在训练集上跑 50 个 epoch 后准确率 99.2%、loss 0.02； 换到测试集上准确率只有 60.4%。训练 loss 曲线一路平滑下降，验证 loss 从第 8 个 epoch 起 开始掉头上扬。数据没有泄漏，测试集分布也算干净。

🔍 病因：模型容量 > 数据信息量

这是机器学习最经典的病症。训练集准确率很高、验证/测试集明显更低，且验证 loss 出现谷底后回升，几乎可以确诊为过拟合（overfitting）。

本质是模型参数太多、数据太少或训练太久，模型学会了去拟合训练样本里的噪声，而不是可迁移的真实规律。用偏差-方差的语言说：模型 方差（variance）过大，换一个测试样本预测就抖得厉害。它的相邻病症是「欠拟合」，差异很好看：

指标过拟合欠拟合
训练 loss很低下降困难，长期偏高
训练/验证差距差距很大差距很小但都很差
处方方向限制模型/增加数据（降方差）增大容量/加特征（降偏差）

为什么选项 A、B、D 不算错？因为如果只把训练集重标一遍（A），99% → 60% 的落差依然客观存在；学习率过小（B）只会让 loss 下降更慢、表面"看起来像没训完"，但这里验证 loss 已经上扬了；测试集太小（D）只会让误差棒变宽，不会让验证 loss 掉头。

💊 处方：降方差四件套

  • 正则化：L2 权重衰减（weight_decay=0.01），对大权重施加惩罚 \(\mathcal{L} = \mathcal{L}_{\text{task}} + \lambda \lVert \theta \rVert_2^2\)
  • Dropout：训练时以概率 \(p\)（常取 0.1–0.3）随机丢弃激活值，逼模型不要依赖单一路径， 等价于对指数多个子网络做集成
  • 早停（Early Stopping）：监控验证指标，连续 patience=3 个 epoch 不提升就停止， 并回滚到最优 checkpoint。这是最便宜的一味药
  • 数据增强 / 增加数据：文本可用回译、同义替换、EDA；更大的语料是根治手段
  • 降低模型复杂度：减层数、减维度、对嵌入层做共享或冻结
🩺 主治医师备注：诊断过拟合不靠"训练准确率高"这一条，而要看验证 loss 曲线的形状。 训练 loss 单看没有意义，一定要有 held-out 集作为体温计。真实项目里，先在 3 个 epoch 内确认模型能过拟合一个小批量（ overfit-a-tiny-batch 自检），再放开训练，能避免 80% 的"参数调不通"。
02

🐢 怎么学都学不会的"榆木脑袋"

难度 ★★ 欠拟合 模型容量 / 优化
病人症状 用一个只有 2 层、隐藏维度 16 的小模型做 10 类情感分类。 训练 200 个 epoch 后，训练 loss 停在 2.21 附近几乎不动（随机猜测约 2.30）， 训练准确率 13%，测试准确率 12%。学习率试过 1e-2 到 1e-5 都差不多。

🔍 病因：模型"脑容量"不够，或输入信息被压没了

训练集都学不好（训练 loss 卡在随机水平、训练准确率 ≈ 测试准确率 ≈ 瞎猜）是欠拟合（underfitting）的典型体征。 注意和病历 01 的区别：过拟合是训练好、验证差；欠拟合是两者都差。

可能的具体病因：

  • 容量不足：隐藏维度 16 对 10 类任务严重偏小，模型没有足够的函数逼近能力去切分决策边界。
  • 特征/表示瓶颈：只有一个池化层或用了平均词向量，序列里的关键区分信息被平均掉了。
  • 优化受阻：学习率不当、缺少归一化层（LayerNorm/BatchNorm）、初始化方差过小（激活值全部塌缩）。
  • 输入被截断：max_length 设得过小，把判断情感的关键句尾全截没了。

为什么不是 A：加正则只会让欠拟合更严重——正则的作用是压制方差，而这里的问题是偏差。C 也不对，脏标签通常带来高训练准确率下异常的输出分布，不会让 loss 停在随机值。D 更无关：换硬件不改变函数逼近能力。

💊 处方：提偏差三板斧

  • 先做可行性自检：拿 64 条样本，关掉正则，看能不能训到 loss ≈ 0。 如果一个小批量都过不了拟合，那就是代码或容量问题，不是数据问题。
  • 加大容量：隐藏维度 16 → 256，层数 2 → 4，或直接用预训练编码器（BERT/中文 RoBERTa）做基础。
  • 改善优化：换 AdamW，加 LayerNorm，检查初始化；用 lr finder 找一个 loss 下降最陡的学习率。
  • 补足表示：用 [CLS] 池化替代 mean pooling；增加 max_length 并核对截断策略。
\(\text{Total Error} = \text{Bias}^2 + \text{Variance} + \sigma^2\)
欠拟合要压的是 \(\text{Bias}^2\)（提高模型复杂度），过拟合要压的是 \(\text{Variance}\)（限制复杂度）。 方向搞反，越调越糟。
🩺 主治医师备注："训不动"和"训太好"是两种完全相反的病，但很多工程师第一反应都是"再加点正则"。 请永远先看四条曲线：训练 loss、验证 loss、训练/验证准确率。它们的关系就是化验单。
03

🎢 坐过山车的损失值

难度 ★★★ 梯度爆炸 RNN / 深层网络
病人症状 训练一个 LSTM 语言模型。前 200 步 loss 从 5.1 降到 4.8， 随后开始剧烈震荡：3.2 → 9.7 → 2.1 → 14.3 → NaN。 开启 torch.autograd.set_detect_anomaly(True) 后，反向传播中某层的梯度范数一路飙到 1e+9 量级。

🔍 病因：连乘效应让梯度指数放大

循环网络沿时间展开后，反向传播要穿过 \(T\) 个时间步的雅可比矩阵连乘：

\(\frac{\partial \mathcal{L}}{\partial h_1} = \frac{\partial \mathcal{L}}{\partial h_T}\prod_{t=2}^{T}\frac{\partial h_t}{\partial h_{t-1}}\)

如果每一步的谱范数 \(\lVert J_t \rVert > 1\)，连乘 \(T\) 次就是指数增长；反之 \(< 1\) 就指数衰减。这就是梯度爆炸与梯度消失其实是同一枚硬币的两面。

表现梯度爆炸梯度消失
梯度范数指数增大、常见 inf/NaN趋近 0，深层几乎不更新
loss 曲线剧烈震荡后 NaN平稳但长时间不降
典型场景RNN/LSTM 长序列、lr 过大、无归一化深层前馈网络、饱和激活（sigmoid/tanh）

本例梯度范数冲到 1e+9、loss 直接 NaN，是爆炸的确证。B 的症状应该是"梯度范数 ≈ 0、loss 长时间不降"，与这里相反。C 的过拟合不会造成 loss 数值爆炸。D 长句只是放大镜，删掉它等于把体温计扔掉——换个长句还会复发。

💊 处方：裁剪 + 稳定化

  • 梯度裁剪（首选）：按全局范数裁剪，把 \(\lVert g \rVert\) 限制在阈值 \(c\) 内：
    \(g \leftarrow g \cdot \min\!\left(1, \frac{c}{\lVert g \rVert_2 + \varepsilon}\right),\quad c \in [0.5, 1.0]\)
    一行 torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0) 就能救命。
  • 降学习率 + warmup：爆炸常由 lr 过大触发，前 1–2% 步数线性 warmup 非常有效。
  • 更稳的初始化：正交初始化 / Xavier，把循环矩阵的谱半径往 1 附近推。
  • 结构改良：换 GRU / 加 LayerNorm / 用 Transformer（自注意力路径更短，系统性缓解连乘问题）。
  • 混合精度注意：fp16 的动态范围小，训练时应开 loss scaling。
🩺 主治医师备注：把梯度范数打到 TensorBoard 上和 loss 并排看，是排查数值问题的第一动作。 梯度裁剪几乎零成本，所有 RNN/长序列训练都建议默认开启，阈值 1.0 是一个很安全的起点。
04

👻 前面几层"装死"的网络

难度 ★★★ 梯度消失 深层网络 / 激活函数
病人症状 一个 12 层的全连接网络，激活函数是 sigmoid。 loss 能下降但极慢，最终停在明显高于基线的位置。可视化逐层梯度范数后发现： 第 12 层梯度约 1e-2，第 6 层 1e-6，第 1–3 层 < 1e-9——几乎等于零。 把网络砍到 2 层，效果立刻变好。

🔍 病因：激活函数把梯度"吃"掉了

sigmoid 的导数最大只有 \(\sigma'(z) \le 0.25\)，一旦输入落到饱和区（\(|z| > 4\)），导数趋近 0。层与层之间连乘：

\(\frac{\partial \mathcal{L}}{\partial W_1} = \frac{\partial \mathcal{L}}{\partial a_L}\prod_{l=2}^{L}\big(W_l^{\top}\,\sigma'(z_{l-1})\big)\)

12 层 × 每层最多 0.25，上界已经衰减到 \(0.25^{11} \approx 2.4\times10^{-7}\)，再叠加权重矩阵的收缩效应，浅层梯度直接进入 1e-9 量级。这正是"浅层装死、loss 缓慢"的成因。

关键的鉴别点：本例梯度范数逐层递减（越靠前越小），而病历 03 是整体暴涨到 1e9。一个看梯度范数的绝对值，另一个看它的层间趋势。B、C 都与"浅层梯度趋零"这一化验结果无关。

💊 处方：让梯度有"高速公路"

  • 换激活函数：ReLU / GELU / SiLU 在正区间导数为 1，从根本上避免饱和（注意 ReLU 的 dying-ReLU 问题，可用 LeakyReLU 或 GELU）。
  • 残差连接：\(y = x + F(x)\)，反向时恒等路径的梯度是 1，直接绕过连乘衰减，这是 ResNet 与 Transformer 的核心。
  • 归一化层：LayerNorm / BatchNorm 把每层输入重新标准化，抑制协变量偏移，稳定梯度尺度。
  • 门控结构：LSTM / GRU 用门控给梯度开"记忆通道"。
  • 合适的初始化：He 初始化（配 ReLU）、Xavier（配 tanh），让各层方差守恒。
🩺 主治医师备注：梯度的"层间分布"是一张极有价值的体检图。凡是出现逐层指数衰减（或放大）， 基本都能靠残差 + 归一化 + 合适激活这"现代架构三件套"解决。这也解释了为什么今天的网络动辄几十上百层却比当年的 MLP 更好训。
05

💀 loss 变成 NaN 的一瞬间

难度 ★★★★ 数值不稳定 学习率 / logits 溢出
病人症状 训练一个分类模型，用 nn.CrossEntropyLoss()。学习率手设为 0.5。 第 1 个 step loss 2.30，第 2 个 step 1.87，第 3 个 step 输出 inf，第 4 个 step NaN，此后全部 NaN。 把 lr 改到 1e-5 就正常，但收敛慢得让人想辞职。

🔍 病因：一步迈太大，参数飞出可行域

梯度下降的更新是 \(\theta_{t+1} = \theta_t - \eta \nabla \mathcal{L}\)。 当 \(\eta\) 过大时，一步就能把参数推进 loss 地形的高墙之上；损失函数陡峭区的梯度又更大，于是下一步推得更远——形成正反馈，直接冲出浮点表示范围。

NaN 的具体传播链条：参数爆炸 → logits 变成 \(\pm\infty\) → softmax 出现 \(\exp(\infty)/\exp(\infty) = \text{NaN}\) → 梯度 NaN → 所有参数被污染 → 永远 NaN（不可恢复）。

\(p_i = \frac{e^{z_i}}{\sum_j e^{z_j}} \quad\xrightarrow{z_i \to \infty}\quad \frac{\infty}{\infty} = \text{NaN}\)

选项 A 是彻底的误解（NaN 与收敛无关）；C 方向反了——交叉熵恰恰配合 log-softmax 才是数值稳定的；D 混淆了概念，OOM 会直接抛异常而不是静默产生 NaN。

💊 处方：把步长管住，把数值管稳

  • 降学习率 + warmup：先用 lr finder 找到下降最陡的区间，通常在 1e-4 ~ 3e-4（AdamW）；前 500 步线性 warmup。
  • 梯度裁剪：范数阈值 1.0，防止单步巨幅更新。
  • 用稳定的损失实现：优先 F.cross_entropy(logits, labels)（内部用 log-sum-exp 技巧）， 绝不要自己写 log(softmax(x))。
  • 加归一化与残差，控制激活和 logits 的量级；fp16 训练务必开启 loss scaling。
  • 可恢复性：加 torch.nan_to_num / 梯度有限性断言 + 自动回滚 checkpoint，让训练不至于一次崩死。
🩺 主治医师备注：NaN 是"不可逆伤害"——一旦出现，网络里的参数就永久坏了。 所以要在每一步之后做 torch.isfinite(loss).all() 断言，第一时间定位到是哪一步、哪个模块炸的。 另外记住：lr 从 0.5 改到 1e-5 能用，恰恰说明病根在优化器步长，而非别的。
06

🧩 学会新活，忘了旧手艺

难度 ★★★ 灾难性遗忘 微调 / 持续学习
病人症状 拿一个通用中文大模型做客服话术全参数微调，数据只有 3000 条，训了 3 个 epoch。 微调后客服任务表现极佳（评分 9.2/10），但让它做摘要、写代码、做数学题的能力全面崩塌—— 连"把这句话翻译成英文"都开始胡言乱语。对比微调前的 checkpoint，通用基准平均下降 41%。

🔍 病因：参数空间里的"覆盖写"

预训练把海量知识编码进权重矩阵；全参数微调时，梯度只来自 3000 条客服数据，优化器会把权重整体拉向这一个窄分布的最优解。 那些原本承载"摘要""翻译""代码"能力的参数方向被重写掉了——这就是灾难性遗忘（catastrophic forgetting）。

从几何上看，预训练的解是参数空间里的一个"平坦盆地"，微调数据稀少时梯度噪声大，很容易把这个盆地整块推平。数据越少、lr 越大、step 越多，遗忘越严重（本例 3000 条 × 3 epoch 是高风险组合）。

排除法：欠拟合（A）会表现为客服任务都做不好，与实际相反；分词器（B）会一致性地影响所有任务包括客服；幻觉（D）无法解释"微调前能做、微调后不能做"的对比结论。

💊 处方：参数高效微调（PEFT）为主

  • LoRA / QLoRA（首选）：冻结全部原始权重，只训练低秩增量 \(W' = W + \Delta W = W + BA\)， 其中 \(B \in \mathbb{R}^{d\times r},\; A \in \mathbb{R}^{r\times k},\; r \ll \min(d,k)\)。 原能力被完整保留，只"挂"了一层小补丁。
  • 部分层冻结：只训最后 2–4 层或仅训输出头，保留底层通用表示。
  • 回放（Replay）：在微调数据里混入 5%–20% 的通用语料，把遗忘压下去。
  • 正则约束类方法：EWC 对重要参数加约束 \(\mathcal{L} + \lambda\sum_i F_i(\theta_i - \theta_i^{*})^2\)；LwF 用旧模型输出做蒸馏。
  • 降 lr、减 epoch：微调 lr 通常取预训练的 1/10 ~ 1/100，1–2 epoch 就够。
🩺 主治医师备注：微调后必须做回归评测——固定一套通用能力测试集（MMLU 子集 / 翻译 / 摘要）， 每次上线前跑一遍对照。只看目标任务涨分而不管通用能力，是很多"上线一周后翻车"事故的直接原因。
07

🕶️ 只看开头和结尾的"近视眼"

难度 ★★★ 长文本失效 位置编码 / 注意力
病人症状 把训练时上下文长度 2048 的模型，直接拿去处理 8000 token 的文档做问答。 关键信息放在开头或结尾时，回答准确率约 85%；放在中间第 3000–5000 个 token 处时，准确率掉到 22%。 loss 在训练时是正常收敛的，模型本身并没有损坏。

🔍 病因：两个叠加的机制

第一层——位置外推失效。若用 RoPE 旋转位置编码，位置 \(m\) 处的旋转角是 \(\theta_d = m \cdot \omega_d\)。 训练只见过 \(m \le 2048\)，推理时突然出现 \(m = 8000\)，注意力的相位进入完全没见过的区间， 相对位置关系判断错乱，中段信息首当其冲。

第二层——lost in the middle。即使上下文窗口够长，注意力分布也天然呈现"两头高、中间低"的 U 形： 首个 token 因 attention sink 效应被持续关注（\(\lVert \cdot \rVert\) 上常是 BOS 吸收了大量注意力）， 最近的 token 因位置邻近、语义相关而权重高，中间的长尾段落则被稀释。

排除法：A 无法解释"位置依存"的准确率落差（过拟合按样本随机，不会形成 U 形曲线）；B 分词器问题会造成全局性能下降而非局部特征；C 混淆了检索/利用失败与生成幻觉。

💊 处方：扩窗 + 改注意力分布

  • 位置插值（PI）：把位置按比例压缩，\(m' = m \cdot \frac{L_{\text{train}}}{L_{\text{target}}}\)，让外推位置落回训练区间。
  • NTK-aware / YaRN 插值：按频率维度分别缩放，低频维少插值、高频维多插值，代价更小、效果更好（Llama 系常用）。
  • 长上下文续训：用 8k–128k 长度的语料做少量继续预训练，让模型真正"见过"长位置。
  • 推理侧缓解：把关键信息前置；或用"重排序 + 分块摘要"（把长文档切块，逐块抽取再汇总）， 把 U 形曲线的中段搬回两端。
  • 替代方案：Sliding Window Attention / 稀疏注意力 / RoPE 底座上的 ALiBi 偏置。
🩺 主治医师备注："支持 128k 上下文"和"能在 128k 上用好"是两件事。 上线长文本应用前，请用一份信息位置扫描测试（把答案分别放在 10%、30%、50%、70%、90% 位置各测一遍）画出自己的 U 形曲线， 这比看模型卡片上的标称窗口长度可靠得多。
08

🤥 一本正经胡说八道的"自信病人"

难度 ★★★ 幻觉 检索增强 / 对齐
病人症状 问模型某篇具体论文的作者和发表年份，它流畅地给出了一个格式完美、语气笃定的答案—— 但作者名字是编的、年份也是错的。追问"你确定吗"，它道歉并给出另一个同样错误的答案。 在不含事实性问题的任务（改写、分类）上，它的表现无可挑剔。

🔍 病因：语言流畅性与事实正确性不是同一个目标

语言模型的训练目标是最大化下一个 token 的似然 \(\mathcal{L} = -\sum_t \log P(x_t \mid x_{<t})\)。 这个目标奖励"像人类文本"，而"论文的作者"这个事实只在预训练语料里出现过有限次数， 模型学到的是"人名 + 年份 + 期刊"的格式分布，而不是一个可检索的数据库。

所以幻觉本质上不是"模型坏了"，而是它在信息不足时选择了继续流畅生成，而不是说"我不知道"。 RLHF 阶段如果奖励了"自信回答"的偏好，还会进一步加重这个倾向。

幻觉类型成因典型场景
事实性幻觉知识缺失 / 长尾事实冷门论文、最新事件
忠实性幻觉没遵循给定上下文摘要、RAG 生成
时间性幻觉知识截止时间外询问本月新闻

为什么 C 不完全对：温度 = 0（贪心解码）只能减少"随机编造"，但最可能的下一个 token 本来就是那个错误的答案， 它会稳定地、确定地胡说。为什么 A、D 不对：权重损坏会全面退化，欠拟合不会只错在长尾事实上。

💊 处方：三管齐下

  • RAG 接地（最有效）：先检索真实文档，再让模型只依据检索片段作答，并在提示词里明确写 "若资料中没有答案，回答'资料中没有提及'"。把闭卷考试改成开卷考试。
  • 拒答/不确定性训练：在 SFT/DPO 数据里加入"不知道就说不知道"的正样本，用偏好优化奖励诚实。
  • 解码与提示技巧：self-consistency（多次采样投票）、Chain-of-Verification（先答再自检）、 要求模型给出引用来源并逐句核对。
  • 后验校验：对关键实体/数字做程序化事实核查（正则提取 + 外部知识库比对）。
  • 换更合适的采样参数：事实问答建议 temperature 0.0–0.3，降低发散。
🩺 主治医师备注：对幻觉不要抱"根除"的期待，要按风险分层处理：医疗、法律、金融场景必须强制引用来源 + 人工复核； 创意写作场景则可以容忍。另外记住那句经验："模型的自信程度与正确率之间几乎没有相关性"。

🔁 复读机式的"卡带病人"

难度 ★★ 重复退化 解码策略 / 数据分布
病人症状 让模型写一段产品介绍，它输出： "我们的产品性能优异，性能优异，性能优异，性能优异……"，一直重复到触发 max_new_tokens。 在抓取来的网页爬虫语料上微调过之后，这个现象明显加重。 另外问它复杂问题时，它总给一句"这是一个很好的问题，让我来回答"然后就没有然后了。

🔍 病因：自回归的"回音室效应"

自回归生成把自己刚生成的文本当作下一轮输入。一旦某个短语被生成，它进入上下文后就成了强证据： \(P(x_{t+1} = \text{"性能优异"} \mid \text{上文含"性能优异"})\) 被显著抬高， 于是模型越来越确信应该继续重复——形成正反馈循环。这是曝光偏差（exposure bias）的直观体现。

三个加重因素：

  • 训练数据重复：爬虫语料里同一句话反复出现，模型学到了"重复是正常的"分布。（本例明确命中）
  • 解码策略：beam search 在长生成上天然偏好"安全、高频"的延续，重复概率更高；纯贪心解码也容易锁死。
  • 训练不足 / 无 EOS：模型没学好"何时该结束"，于是靠重复填充 token 预算。

"输出很短的通用回复"是同一病根的另一面：SFT 数据里大量礼貌性套话且长度偏短，模型学到"长回答风险大，短回答最安全"。 排除 B（梯度问题会造成 NaN 而非结构化的重复）、C（重复是分布问题不是容量问题）、D（OOM 会直接报错）。

💊 处方：解码层 + 数据层双管齐下

  • 重复惩罚：repetition_penalty=1.05~1.2，对已出现 token 的 logit 做惩罚 \(z_i \leftarrow z_i / p \;(z_i>0)\)。
  • 采样组合：temperature=0.7, top_p=0.9, top_k=50—— temperature 调高、top-p 截断长尾，能显著降低死循环。
  • no_repeat_ngram_size=3~4：硬性禁止 3-gram 重复，简单粗暴但有效。
  • 数据清洗（根治）：对训练语料做 MinHash / SimHash 去重，去除模板化文本， 这是本例最该做的一步。
  • 训练侧：确保样本包含完整 EOS；对"太短/太泛"的回答做负样本、对详细回答做正样本（DPO）。
🩺 主治医师备注：看到重复，先问"训练语料里有重复吗"。 很多工程师在解码参数上反复试，但真正的病根在数据——同一句话出现十万次的语料，无论怎么调参数都会让模型觉得重复是常态。 去重一小时的收益，常常大于调参一周。

💥 显存撑爆的"大胃王"

难度 ★★★ OOM 显存管理 / 分布式
病人症状 在 24GB 显卡上微调 7B 模型，batch size=8、seq_len=2048、AdamW 全参数训练。 启动即报 CUDA out of memory. Tried to allocate 2.00 GiB。 把 batch size 降到 1 依然 OOM。

🔍 病因：算一笔显存账就清楚了

全参数训练 7B（fp16 权重）时，每一份参数要配四类开销：

项目精度大小
模型权重fp16 (2B/参数)7B × 2 = 14 GB
梯度fp16 (2B/参数)7B × 2 = 14 GB
AdamW 优化器状态 (m, v)fp32 ×2 (8B/参数)7B × 8 = 56 GB
激活值（batch 相关）fp16与 batch × seq_len 成正比

合计静态开销已超过 80GB，远超 24GB。这也解释了为什么"batch size 降到 1 还是 OOM"——静态部分就已经装不下了， 减小 batch 只影响激活值那一项。

\text{Memory}_{\text{train}} \approx \underbrace{2P}_{\text{权重}} + \underbrace{2P}_{\text{梯度}} + \underbrace{8P}_{\text{Adam 状态}} + \underbrace{A(b, s, L)}_{\text{激活}}

排除法：A 不是硬件故障（换个 80GB 卡能跑，但那是用钱解决问题）；B 梯度爆炸不会造成稳定的启动即 OOM； D 方向反了——seq_len 越大显存越高。

💊 处方：从这五条里按需组合

  • ① 梯度累积（零成本，先做）：gradient_accumulation_steps=16， 用小 batch 累积出等效大 batch，显存立刻降一个量级。
  • ② LoRA / QLoRA（性价比最高）：只训 \(r=8\!\sim\!64\) 的低秩矩阵， 可训练参数降到原来的 0.1%–1%，优化器状态几乎消失；QLoRA 再把基座 4-bit 量化，7B 模型单卡 24GB 可训。
  • ③ 混合精度 + 8-bit 优化器：bf16/fp16 计算，bitsandbytes 的 8-bit Adam 把 56GB → 14GB。
  • ④ 梯度检查点（Gradient Checkpointing）：用时间换空间，激活显存降约 \(\sqrt{L}\) 倍（多花约 30% 时间）。
  • ⑤ ZeRO / 分布式：ZeRO-2 分片优化器状态与梯度，ZeRO-3 连权重一起分片， 配合 device_map="auto" 或 FSDP 做多卡切分。
方案组合LoRA + bf16 + grad_ckpt
7B 微调显存占用≈ 10–14 GB（24GB 单卡可跑）
可训练参数占比≈ 0.5%（约 400 万参数）
相对全参训练显存 ↓ 约 6×，速度 ↓ 约 1.3×
🩺 主治医师备注：OOM 的第一动作永远是算账，而不是瞎调参数。 用上面的公式把 2P+2P+8P 估一遍，就知道瓶颈在哪一项。经验值：24GB 单卡配 LoRA 可以舒适地微调 7B； 要全参数微调 7B，至少准备 4×80GB 或者直接上 ZeRO-3。

🏆 业绩好到不真实的"天选之子"

难度 ★★★ 数据泄漏 评测流程
病人症状 一个文本分类任务，离线评测 AUC 0.997，团队准备直接上线。 上线后线上 AUC 只有 0.63，比随机好一点。 复查数据处理代码发现：划分训练/测试集之前，先对全量数据做了归一化和 TF-IDF 拟合 （即 fit_transform 用在了整个数据集上），且同一用户的多条样本被随机拆到了训练集和测试集两边。

🔍 病因：测试集的信息"偷渡"进了训练流程

数据泄漏（data leakage）指训练过程中以任何形式接触到了测试集的信息。这里有两处泄漏：

  • 预处理泄漏：TF-IDF / 归一化的统计量（词频、均值、方差）本应从训练集单独拟合， 却用了全量数据。测试集的词汇分布信息被写进了特征空间，模型"提前看到了考题"。
  • 分组泄漏：同一用户的多条记录被随机拆开，训练集里已经出现了测试集用户的相似样本， 模型只需记住用户特征就能答对——这是离线 0.997 却线上 0.63 的真正杀手。

鉴别要点：0.997 这种"好到不真实"的指标，第一反应就应该是"是不是泄漏了"。 真实的分类任务，尤其是用户行为类任务，AUC 到 0.8–0.9 已经相当不错。

为什么 B 不对：过拟合是模型层问题，加正则可能把指标降下来，但仍然不诚实地虚高， 因为泄漏在数据管线里没被清除。为什么 C 片面：环境不一致只解释"线上低"，不解释"离线高得离谱"。

💊 处方：让管线先划界，再拟合

  • 先划分，后拟合：严格 train_test_split → fit on train → transform on test， 用 sklearn 的 Pipeline 从结构上杜绝。
  • 分组划分：同用户/同文档/同时间段的数据必须整组进同一边，用 GroupShuffleSplit； 时间序列任务用时序划分，绝不用随机划分。
  • 去重：训练集与测试集做精确 + 近邻去重（MinHash/SimHash），防止同一样本以变体形式同时出现。
  • LLM 时代的新泄漏：评测集可能已进入预训练语料，出现"刷榜虚高"。 需用私有测试集或动态更新的新数据评测。
  • 制度：指标异常好时，先做"标签洗牌测试"——把标签打乱重训，若指标仍高，必有泄漏。
🩺 主治医师备注："太好了"往往比"太差了"更危险。 在医疗、金融风控这类高风险场景，一个被高估的离线指标可能导致完全错误的业务决策。 请把数据泄漏审计作为模型上线的强制关卡。

🚶 一直在谷底来回横跳的"迷路者"

难度 ★★★ 学习率不当 调度器 / 优化器
病人症状 loss 从 4.6 快速降到 2.1，然后就开始在 2.08 ~ 2.19 之间 来回抖动，3000 步内再没下降。放大 loss 曲线能看到明显的锯齿。 训练准确率在 71% 附近震荡。当前配置：AdamW，lr=1e-3 恒定不变，无调度器。

🔍 病因：步长 > 谷底宽度，于是来回蹦

loss 先快速下降、然后进入锯齿状平台，是学习率过大的经典签名： 参数在极小值附近的陡壁之间来回弹跳，无法收敛到谷底。

\theta_{t+1} = \theta_t - \eta \nabla \mathcal{L}(\theta_t)

当 \(\eta > \frac{2}{\lambda_{\max}}\)（\(\lambda_{\max}\) 是 Hessian 最大特征值）时， 迭代甚至可能发散；接近这个边界时，就表现为这种"下降后震荡"。

三种学习率病症的鉴别：

症状诊断处理
loss 下降极慢、几乎不动lr 太小提高 lr 或换自适应优化器
loss 快速下降后剧烈震荡lr 太大（本例）降 lr + 加调度器
loss 突然爆 NaNlr 过大到发散降一个量级 + warmup

排除法：欠拟合（A）不会出现"先降后震"的形状；梯度消失（C）会让 loss 一直平着不动，不会有下降段； batch size（D）影响的是梯度噪声与收敛稳定性，但恒定 lr=1e-3 配 AdamW 本身就是高风险配置。

💊 处方：给学习率一条曲线，而不是一个常数

  • Warmup：前 1%–5% 的步数从 0 线性升到峰值，避开训练初期梯度方向混乱的阶段。 \(\eta_t = \eta_{\max}\cdot\frac{t}{T_w},\; t \le T_w\)
  • Cosine Decay（首选）： \(\eta_t = \eta_{\min} + \tfrac{1}{2}(\eta_{\max}-\eta_{\min})\left(1+\cos\tfrac{t\pi}{T}\right)\)， 后期自动把步长收到很小，帮助模型落入谷底。
  • OneCycle / 余弦退火重启：单周期先升后降，常能同时提速和提质。
  • LR Finder：从 1e-7 指数增长到 1，画 loss-lr 曲线，取最陡下降段的中点作为峰值 lr。
  • 调参顺序：先把 lr 调对，再调 warmup 比例，最后调权重衰减。
峰值学习率（AdamW）1e-5 ~ 5e-4（LLM 微调常用 2e-4）
Warmup 比例1% ~ 5%
最终学习率峰值的 1% ~ 10%
经验法则lr 与 batch size 大致线性缩放
🩺 主治医师备注：现代训练几乎不用恒定学习率，调度器的收益是"免费的性能"。 看 loss 曲线的形状（而非绝对值）就能判断 lr 是否合适： 锯齿平台 → 太大；直线缓降 → 太小；平滑收敛 → 刚好。
