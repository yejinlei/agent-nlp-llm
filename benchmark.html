📐怎么真正评估一个模型

① 看基准测试（但要警惕）

MMLU（通用知识）、HumanEval（代码）、C-Eval / CMMLU（中文）、GSM8K（数学推理）。注意：基准分数可能因数据污染、提示方式差异而虚高，只能作为粗筛。

② 语言模型困惑度 PPL

PPL 越低说明模型对文本的"意外程度"越小。公式 \( \text{PPL}=\exp\!\big(-\frac{1}{N}\sum_i \log p(w_i)\big) \)。但 PPL 低不等于任务表现好，只能衡量语言流畅度。

③ 在自己的数据上测

这是唯一真正靠谱的办法。从你的真实任务里抽 100–300 条，人工标注参考答案，做成自己的评测集。别人的榜单不如自己的测试集。

④ 算清成本

API 按 token 计费要算清输入输出比例；本地部署要算显卡折旧 + 电费 + 运维。很多时候"自己部署"并不比 API 便宜，除非量大或隐私硬要求。

选型心法： 先被约束筛选（隐私、预算、延迟），再在剩余候选里做实测对比，最后用成本归一化——每块钱效果最好的那个，才是你该选的模型。
