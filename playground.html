01🎯 为什么"玩"比"读"更有效

语言模型的知识有一半是形状而不是定义。"注意力是一个加权平均"这句话没有形状； 但当你在热力图上看到 \( \text{它} \) 这一列烧得最红时，你就有了形状。 玩法页面的全部目的，就是把定义变成形状。

🧱

把黑箱拆成看得见的零件

大模型是一个 70 亿到 4000 亿参数的函数。你不能"看懂"它，但你可以拆开其中每一颗螺丝看它怎么转—— 分词器怎么切、向量怎么算、注意力看哪里。

🔁

用最小反例建立直觉

每个玩法都提供一个"极端输入"入口：把词表调到最小、把温度调到最高、把句子换成生僻词。 直觉是在边界条件上长出来的，不是在正常例子上。

🪜

四步教学法贯穿始终

每个玩法页面内部都按「直觉 → 数学 → 代码 → 实战」组织。先让你产生疑问，再用公式解释， 再用代码复现，最后告诉你工业界真实数字长什么样。

一句话总纲：凡是你能在 30 秒内用一个滑块、一个输入框或者一次点击复现的东西，你都不会真正忘记它。 这个广场就是把 NLP／LLM 里所有"值得复现"的概念都做成了那个滑块。

03🧪 现场试玩：一口 BPE

不用跳转，这里就能先尝一口最核心的玩法。下面这个迷你 BPE 和 bpe.html 里的是同一套算法，只是把词尾标记 </w> 简化掉了， 让第一次合并看一眼就懂。

Mini BPE · 只做一步合并

BPE 的全部逻辑只有一句话：统计相邻符号对，把出现次数最多的那一对粘起来。 这个框里做的就是这个"统计 + 粘合"。

✍️ 输入约定：用空格把符号分开（如 l o w 表示三个符号）， 用逗号或换行分隔不同的词。默认值已经是最小可玩的例子——直接点按钮就行。

符号总数0

相邻符号对频次排行（Top 6）

点上方按钮，开始统计。
📌 这是什么意思：每合并一次，序列就短一点，而词表里多了一个"新符号"。 合并的次数就是 BPE 唯一的超参数——想得到 5 万个 token 的词表，就合并 5 万次（去掉初始 256 个 byte 之后）。 这就是"用合并次数换词表大小"。

为什么不是"按词切分"？

按词切分，词表要无穷大，而且任何一个没见过的词都变成 <UNK>； 按字符切分，词表很小，但序列变得极长、单个字符几乎没有语义。 子词（subword）取中间：高频的词整块保留，低频的词拆成有意义的碎片， 于是 "lowest" 才有可能拆成 "low" + "est" 而不是五个无意义的字符。

为什么"最常见"要合并？

语言里存在 Zipf 定律：少数词出现得极多，大多数词出现得极少。 把 p("th" 相邻) 这种高频碎片粘成一个 token，能让整篇文本的 token 数显著下降， 等价于在同样上下文窗口里塞进更多真实文字。压缩率和词表大小，就是 BPE 唯一的权衡轴。

05📖 玩法使用指南

关于怎么用这些页面，以及它们背后的做法，写在下面这些折叠区里。

🎮 怎么玩才有效：三条实操建议
  • 先预测，再点击。按下"运行"之前，先在脑子里猜一下输出长什么样。猜错的那一次，就是真正学到东西的那一次。
  • 一定要走到极端。每个 Demo 都往边界推一把：输入纯中文、输入纯 emoji、输入一段代码、把参数拉到最大和最小。边界条件暴露的是原理，不是参数。
  • 玩完看一眼"这是什么意思"。每个 Demo 下面那段蓝色提示框才是知识点本体，交互只是让这个知识点长出了形状。
⚙️ 这些 Demo 是真算还是假演？

全部是真算。所以这个站点可以在完全离线的情况下打开（KaTeX 公式字体除外）。 具体来说：

  • BPE 页面：由你在输入框里提供的文本现场构建语料、现场统计相邻对频次、现场执行合并。你改成什么文本，结果就跟着变。
  • 词向量页面：使用一组预置的二维示意向量做真实的向量加减与最近邻搜索，不是查表。
  • 注意力页面：按照 scaled dot-product attention 公式 \( \text{softmax}(QK^\top/\sqrt{d}) \) 现场计算权重，再按权重映射成颜色。
  • 决策树页面：走的是真实的 if-else 决策逻辑，每个分支都有明确的工程依据。
唯一的例外是"示意维度"。真实的词向量是 300 到 4096 维，页面上不可能画 4096 维空间， 所以会降维到 2 维或 3 维展示。但降维只影响画给你看的样子，不影响计算结果。

🔧 技术实现：为什么可以做到零依赖
  • 纯静态。没有构建步骤、没有 npm、没有打包器。所有页面都是可以直接双击打开的 HTML 文件。
  • KaTeX 渲染公式。数学公式用 KaTeX 语法写在 class="math" 的容器里，加载时自动渲染，不依赖 MathJax 那种重量级方案。
  • 原生 DOM 操作。交互全部用原生 JavaScript 完成，没有任何前端框架。每个 Demo 是一个独立的立即执行函数，互不干扰。
  • 算法与教学分离。每个页面的结构都是「先用直觉描述 → 再给数学 → 再给可运行代码 → 最后给工业界真实数字」，交互组件嵌在直觉那一段里。

06❓ 常见疑问

我完全不懂数学，能玩吗？

可以。每个玩法都会先用一段没有任何符号的话把直觉说清楚，公式都放在"数学"那一段， 并且每个符号都有解释。跳过公式只看交互和提示框，也能拿到七成的收获。

需要先看完 index.html 吗？

不需要。玩法广场本身就是最好的入口。但如果你想先建立整体地图， 首页的"六级学习路径"和"全景家族树"值得花十分钟扫一遍。

为什么同一个概念有多个玩法？

因为不同的抽象层级需要不同的入口。比如"分词"这件事， BPE 页面看的是算法， LLM 手册看的是工程取舍， 选型页面看的是它对成本的影响。三个视角合起来才是完整的。

可以在手机上玩吗？

可以，全部页面都是响应式的，导航栏在窄屏会折叠成汉堡菜单。 不过注意力热力图这类需要横向空间的 Demo，横屏或平板体验更好。
