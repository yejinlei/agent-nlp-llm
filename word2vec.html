Word2Vec 从零 🧠

词向量不是"算"出来的，是"训练"出来的。这一页把词向量的完整链路摊开：从共现矩阵 → PMI → SVD，到 CBOW → Embedding 层 → 负采样的高速化，每一步都有可跑的代码和能点的交互。

🎯 一句话抓住本质

word2vec 的核心思想只有一句：用"上下文"去预测"中心词"，让经常出现在相似上下文里的词，学到相似的向量。

它不是查字典，而是解一道巨大的"完形填空"题。做完之后，词义就自动被编码进了向量。

0. 为什么需要词向量？

计算机不认识"猫"，只认识数字。最原始的做法是 one-hot 编码：词典里第 3 个词，就表示成 [0,0,1,0,0,...]。

one-hot 的致命缺陷：任意两个不同词的余弦相似度都是 0，"猫"和"喵"之间的关系，和"猫"和"冰箱"之间，在数学上一模一样。它也完全无法表达"国王 − 男人 ≈ 女王 − 女人"这种语义运算。

我们需要的是：让每个词变成一个稠密的、低维的、能表达语义的向量。而且——关键——这个向量最好能从数据里自动学出来，不用人工标注。

分布式假设（Distributional Hypothesis）：一个词的含义，由它经常出现的上下文决定。词义相近的词，出现的上下文也相近。这是整个词向量大厦的地基。

1. 基于计数的方法：共现矩阵

最直觉的做法：统计每个词周围都出现哪些词，做成一张表。这就是共现矩阵（co-occurrence matrix）。

先看一段最经典的玩具语料：

corpus = [
  "you say goodbye and i say hello .",
  "i say hello and you say goodbye .",
]

约定看窗口大小为 1（只看左右各一个词）。以 "say" 为例，它左右出现的词是 you / goodbye / i / hello，所以这些位置的计数 +1。把所有词都统计一遍，得到共现矩阵（这里用对称计数）：

行 = 中心词，列 = 上下文词。行向量就是该词的"计数量子化表示"。

为什么余弦相似度而不是欧氏距离？因为词频差异会让向量长度差异巨大，但我们关心的是方向（语义模式），不是长度。余弦相似度 cos(a,b) = a·b / (|a||b|) 只看向量夹角，天然对长度不敏感。

2. 从"数次数"到"看关联"：PMI 点互信息

共现矩阵有个问题："the"这种高频词和谁都共现很多次，这会淹没真正的语义关联。解决办法是引入 点互信息（PMI, Pointwise Mutual Information）：

PMI(x, y) = log₂ ( P(x,y) / (P(x)·P(y)) )

它的含义很直观：两个词一起出现的概率，比"各自独立出现的概率相乘"高出多少倍。

  • 如果 x 和 y 完全独立 → 分子分母相等 → PMI = 0
  • 如果高度关联（如"哈"和"利"）→ 分子远大于分母 → PMI 是个大正数
  • 如果互相排斥 → PMI 为负

由于 PMI 在低频词上会爆炸（出现 1 次就可能算出巨大值），实践中常用 正 PMI（PPMI）：把负值全部截断为 0。

import numpy as np

def ppmi(C, eps=1e-8):
    """C: 共现矩阵 (N x N)"""
    N = C.shape[0]
    total = C.sum
    S = np.zeros_like(C, dtype=np.float64)
    for i in range(N):
        for j in range(N):
            p_ij = C[i, j] / total
            p_i  = C[i, :].sum / total
            p_j  = C[:, j].sum / total
            if p_ij == 0:
                continue
            val = np.log2(p_ij / (p_i * p_j + eps) + eps)
            S[i, j] = max(0.0, val)   # 负值截断为 0
    return S

3. 降维利器 SVD：让稠密向量浮出水面

PPMI 矩阵有两大问题：① 维度等于词表大小（可能上百万维）② 非常稀疏（大多数格子是 0）。我们要把它压成稠密低维向量，靠的是 奇异值分解（SVD）。

X = U · Σ · Vᵀ

其中 Σ 是对角矩阵，对角线上的奇异值按从大到小排列。我们只取前 k 个最大奇异值，就把 N 维压成了 k 维（比如 100 维）。用 numpy 一行就能算：

U, S, Vt = np.linalg.svd(ppmi_matrix, full_matrices=False)

# 只用前 2 维做可视化，或前 100 维做实际词向量
k = 2
X_reduced = U[:, :k] * S[:k]     # 每个词的 k 维稠密向量

# 画到二维平面上，语义相近的词会聚在一起
import matplotlib.pyplot as plt
for i, word in enumerate(vocab):
    plt.annotate(word, xy=(X_reduced[i,0], X_reduced[i,1]))
plt.scatter(X_reduced[:,0], X_reduced[:,1])
plt.show
为什么 SVD 能保留语义？因为奇异值大的方向，正是数据里"变化最剧烈"的主成分。把小的奇异值丢掉，相当于扔掉了噪音和细枝末节，留下的是词与词之间最本质的关联结构。

4. 基于推理的方法：CBOW 登场

上面这套"计数 + SVD"叫基于计数的方法。它有个大毛病：语料一变就得重算整个矩阵和 SVD，代价极高。

word2vec 走的是另一条路——基于推理的方法：用一个神经网络去预测中心词，训完之后，网络的权重就是词向量。

🧩 CBOW = Continuous Bag-of-Words

输入：上下文（左右各 N 个词）→ 输出：中心词的概率分布

例：给 "you" "goodbye" "i" "hello"（上下文），让网络猜中间那个词是 "say"。

网络长什么样？

CBOW 是一个只有两层的超简单神经网络：

① 输入层

上下文词的 one-hot 向量

② 中间层

权重 Win（V×H），把 one-hot 压成 H 维

③ 输出层

权重 Wout（H×V），再 softmax 出概率

关键洞察：输入层的 one-hot × Win，等价于"直接从 Win 里挑出对应那一行"。所以 Win 的每一行，天然就是那个词的向量！

5. CBOW 的正向传播与反向传播

正向：上下文 one-hot 求平均

把左右上下文词的 one-hot 平均后乘 Win，得到中间层 h。为什么"平均"？因为 CBOW 把上下文当作一个"袋子（bag）"，不区分顺序。

正向：中间层 → 得分 → softmax

中间层 h 乘以 Wout 得到每个词的得分，再经过 softmax 变成概率。交叉熵损失衡量预测分布与真实 one-hot 的差距。

反向：梯度从输出层流回输入层

课本用计算图一步步推导，最终得到两条极简洁的更新式：

∂L/∂Wout = hᵀ · (ŷ − y)　　∂L/∂Win = x · (ŷ − y) · Woutᵀ

其中 ŷ − y 就是"预测概率减真实标签"，这个差越大，说明错得越离谱，权重调整越多。

从零实现的核心只有这几行： 
class SimpleCBOW:
    def __init__(self, vocab_size, hidden_size):
        V, H = vocab_size, hidden_size
        # Xavier 初始化：方差随 fan-in/fan-out 自适应，防止激活值爆炸
        W_in  = 0.01 * np.random.randn(V, H)
        W_out = 0.01 * np.random.randn(H, V)
        self.in_layer  = MatMul(W_in)    # 输入侧全连接
        self.out_layer = MatMul(W_out)   # 输出侧全连接
        self.loss_layer = SoftmaxWithLoss

    def forward(self, contexts, target):
        h = sum(self.in_layer.forward(c) for c in contexts) / len(contexts)  # 平均
        score = self.out_layer.forward(h)
        loss = self.loss_layer.forward(score, target)
        return loss

    def backward(self, dout=1):
        ds = self.loss_layer.backward(dout)
        da = self.out_layer.backward(ds)
        self.in_layer.backward(da / len(contexts))  # 平均的反向要除以个数
        return None

6. Embedding 层：查表就是从矩阵里挑一行

用 one-hot × MatMul 太浪费了——明明是 99% 是 0 的向量在做乘法。直接索引取行就行，这就是 Embedding 层：

class Embedding:
    def __init__(self, W):
        self.params = [W]
        self.grads = [np.zeros_like(W)]
        self.idx = None

    def forward(self, idx):
        W, = self.params
        self.idx = idx
        out = W[idx]      # 一次取行，O(1)
        return out

    def backward(self, dout):
        dW, = self.grads
        dW[...] = 0
        # 同一个词可能被取多次，梯度要累加
        np.add.at(dW, self.idx, dout)
        return None
这带来两个巨大收益：① 计算从 O(V×H) 降到 O(H)，当词表有百万级时差别是数量级的；② 反向传播时只更新被取到的那几行，天然稀疏。

7. 负采样：把十万分类偷换成二分类

CBOW 到了输出层还有个隐藏的"性能杀手"：softmax 要对整个词表算一遍。词表 100 万、H=100 时，输出层一次就要算 1 亿次乘法——根本训不动。

负采样（Negative Sampling）的思路：我们其实不需要"从 100 万词里分出正确的那个"。我们只需要回答一个问题——"这个词是真实存在的上下文吗？是 / 否"。于是十万分类 → 二分类，问题瞬间变简单！

✅ 正样本

真实出现的"上下文—目标词"组合，标签 = 1，比如 ("say" → "goodbye")。

❌ 负样本

随机抽出几个"根本不相关"的词当反例，标签 = 0，比如 ("say" → "冰箱")。每条正样本配 5–10 个负样本即可。

损失函数从"多分类交叉熵"变成"多个二分类的 sigmoid 交叉熵之和"：

L = −log σ(s) − Σk=1..K log σ(−sk)

其中 s 是正样本得分，sk 是第 k 个负样本得分。第一项让正样本得分大，第二项让负样本得分小。

负样本该怎么抽？用 0.75 次方

不能均匀随机抽（"the""a"这种词会被抽爆），也不能按纯词频（稀有词几乎抽不到）。word2vec 的经验做法是按词频的 0.75 次方采样：

def sample_negative(vocab_size, word_freqs, K=5):
    """按 0.75 次方加权采样负样本"""
    freqs = np.array(word_freqs) ** 0.75
    probs = freqs / freqs.sum
    return np.random.choice(vocab_size, size=K, p=probs)

负采样把计算量从 O(V) 降到 O(K+1)，K 通常取 5～10。这是 word2vec 能在大规模语料上跑起来的关键一步，也是"从 0.1 秒到 0.001 秒"的加速来源。

8. skip-gram：另一条岔路

CBOW 是"上下文 → 中心词"。把方向反过来，就是 skip-gram：

CBOW（快但略糙）

多个上下文词 → 预测 1 个中心词。训练快，对高频词友好，低频词信息被"平均"稀释。

skip-gram（慢但更准）

1 个中心词 → 预测多个上下文词。每个词都能作为独立样本，低频词也能学得较好，词向量质量通常更高。

怎么选？语料小、要质量、有时间 → skip-gram；语料大、要速度 → CBOW。GloVe 则是把"计数"和"预测"两种思路融合起来的代表。

9. 怎么评价词向量好不好？

① 相似度

看人打分：给一组词对，人工评"1–10 分"的相似度，再算词向量相似度，求相关系数。

② 类推（类比）

"king − man + woman = ?" 答案应是 queen。这是最出圈的验证方式。

③ 下游任务

直接把词向量喂给分类器，看实际任务（情感分类、命名实体识别）表现。

def analogy(w_a, w_b, w_c, word_vecs, vocab, topn=3):
    """a - b + c = ? """
    target = word_vecs[w_a] - word_vecs[w_b] + word_vecs[w_c]
    # 和所有词算余弦相似度，取最高
    sims = cosine_similarity(target, word_vecs)
    best = np.argsort(-sims)[:topn]
    return [vocab[i] for i in best]
⚠️ 一个常见坑：评价词向量时，所有向量应当先做单位化（归一化），否则范数大的词会在点积里占便宜。很多"类比结果不对"的抱怨，其实是因为忘了这一步。

🧭 一条主线串起来

共现矩阵（统计）→ PMI（去高频噪音）→ SVD（降维稠密化）是"计数派"；

CBOW / skip-gram（预测）→ Embedding 层（高效查表）→ 负采样（提速）是"推理派"。

两派殊途同归，最后都指向同一件事：让语义变成向量，让向量的距离等于语义的距离。
