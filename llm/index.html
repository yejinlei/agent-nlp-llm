🎯 这是什么

大语言模型（Large Language Model, LLM）是基于Transformer解码器架构、在海量文本上预训练的超大规模语言模型。本模块覆盖LLM从底层架构、预训练、对齐、微调、Prompt工程、RAG、Agent到量化部署的全链路技术栈，每个核心算法都遵循「论文→理论→实现→实战」四层闭环。

LLM的核心是Scaling Law：随着模型参数量、训练数据量、计算量的指数级增长，模型能力会线性提升，并且在参数量超过一定阈值后，会涌现出小模型不具备的推理、上下文学习、指令遵循等能力。

① LLM架构基础
Decoder-only 架构（RoPE/GQA/SwiGLU/RMSNorm/MoE）
📄 论文背景

原始Transformer用编码器+解码器结构，GPT系列发现仅用解码器（Decoder-only）架构的生成效果更好。现代大模型（LLaMA/Qwen/DeepSeek）在原始GPT基础上做了大量改进：2021年RoPE旋转位置编码（苏剑林）、2023年GQA分组查询注意力、SwiGLU激活函数替换ReLU、RMSNorm替换LayerNorm、MoE混合专家模型等。

📚 理论原理
  • RoPE旋转位置编码：通过绝对位置的旋转矩阵实现相对位置编码，外推性好，支持长上下文
  • GQA分组查询注意力：KV头数是Q头数的1/4或1/8，注意力效果接近MHA，但KV缓存显存减少75%，推理速度提升2-4倍
  • SwiGLU激活函数：$\text{SwiGLU}(x) = \text{Swish}(xW) \otimes (xV)$，比ReLU效果好，已成为大模型标配
  • MoE混合专家：把FFN拆成多个专家，每个token只激活Top2专家，相同计算量下模型参数量可以翻8倍
💻 核心实现
# RoPE 旋转位置编码核心实现
def precompute_freqs_cis(dim, max_seq_len, theta=10000.0):
    freqs = 1.0 / (theta ** (torch.arange(0, dim, 2)[:dim//2].float() / dim))
    t = torch.arange(max_seq_len)
    freqs = torch.outer(t, freqs)
    return torch.polar(torch.ones_like(freqs), freqs)

def apply_rotary_emb(x, freqs_cis):
    x_complex = torch.view_as_complex(x.float().reshape(*x.shape[:-1], -1, 2))
    freqs_cis = freqs_cis[None, None, :x.shape[2], :]
    x_rot = torch.view_as_real(x_complex * freqs_cis).flatten(-2)
    return x_rot.type_as(x)
🚀 实战要点
  • 现在所有开源大模型都是LLaMA架构变体，基本结构完全一致，只在位置编码、注意力、激活函数上有小改动
  • MoE模型（如Mixtral 8x7B/DeepSeek-V2）推理速度慢，实际部署如果不是显存特别紧张，优先选稠密模型
  • 7B/14B模型用GQA，KV缓存显存占用小，消费级显卡就能跑长上下文
Scaling Law 规模定律
📄 论文背景

2020年OpenAI在《Scaling Laws for Neural Language Models》中提出：大模型的性能（损失）和参数量N、训练数据量D、计算量C呈幂律关系：$L \propto N^{-\alpha_N} D^{-\alpha_D} C^{-\alpha_C}$。只要持续增加计算量和数据，模型性能就能可预测地提升。这是大模型时代最核心的理论基础。

📚 理论原理

核心结论：

  • 模型性能和三个因素都符合幂律关系，不达到瓶颈之前不会饱和
  • 三个因素要匹配：大模型配小数据或小模型配大数据都不行，要同时缩放
  • 当参数量超过临界阈值（大概10B左右），会出现**能力涌现**：突然具备小模型完全没有的推理、代码、数学、多轮对话能力

🚀 实战要点
  • 不是参数越大越好，14B模型用高质量数据训练，效果可以超过70B低质量数据模型
  • Chinchilla定律：最优参数量和训练token数是1:1，即7B模型应该用7T tokens训练才最优，之前的模型普遍训练不足
② 预训练与对齐
三阶段训练流程（预训练→SFT→RLHF/DPO）
📄 论文背景

2022年InstructGPT论文提出RLHF（人类反馈强化学习）三阶段训练流程：大规模无监督预训练→有监督指令微调SFT→基于人类反馈的强化学习对齐人类偏好。ChatGPT就是基于这个流程训练出来的。2023年DPO（直接偏好优化）提出，把RLHF的奖励模型和PPO训练合并成一个损失函数，训练更简单稳定，现在已经基本取代PPO。

📚 理论原理

DPO损失函数：不需要单独训练奖励模型，直接用偏好对优化： $$\mathcal{L}_{DPO} = -\mathbb{E}\left[\log\sigma\left(\beta\log\frac{\pi_w(y_w|x)}{\pi_{ref}(y_w|x)} - \beta\log\frac{\pi_w(y_l|x)}{\pi_{ref}(y_l|x)}\right)\right]$$ 核心思想：让模型更倾向于生成人类偏好的回答$y_w$，降低不偏好回答$y_l$的概率，同时和参考模型$\pi_{ref}$不要差太远。

🚀 实战要点
  • 预训练阶段决定模型的能力上限，占总训练成本99%以上，SFT和对齐只是把能力激发出来、对齐人类偏好
  • 中小团队根本不需要做预训练，只需要做SFT和DPO对齐垂直领域即可，现在开源基座模型能力已经非常强
  • SFT数据质量远重于数量：几万条高质量垂直领域指令数据，效果好于几十万条低质量通用数据
LoRA / QLoRA 参数高效微调
📄 论文背景

2021年微软在《LoRA: Low-Rank Adaptation of Large Language Models》中提出LoRA，冻结大模型全部参数，只在注意力层训练低秩矩阵，训练参数量不到原来的1%，显存占用降低70%以上，效果和全参数微调几乎相当。2023年华盛顿大学提出QLoRA，用4bit量化基座模型+双量化+分页优化器，让48G显卡就能微调65B模型，普通消费级显卡也能微调大模型。

📚 理论原理

核心思想：大模型微调时权重变化矩阵$\Delta W$是低秩的，可以分解为两个小矩阵$B \times A$： $$W' = W + BA, B \in \mathbb{R}^{d\times r}, A \in \mathbb{R}^{r\times d}, r \ll d$$ 训练时只更新A和B，推理时可以把BA合并到W里，没有任何推理延迟。

💻 核心实现
class LoRALayer(nn.Module):
    def __init__(self, in_features, out_features, rank=8, alpha=16):
        super().__init__()
        self.A = nn.Parameter(torch.randn(in_features, rank) * 0.01)
        self.B = nn.Parameter(torch.zeros(rank, out_features))
        self.scale = alpha / rank
    def forward(self, x):
        return x @ self.A @ self.B * self.scale
🚀 实战要点
  • LoRA一般只加在Q和V投影矩阵，rank=8-64就足够，alpha一般设为rank*2
  • QLoRA 4bit量化微调效果和全参数微调差距小于1%，是现在垂直领域微调的首选方案，RTX3090/4090就能微调7B/14B模型
  • 工程坑点：学习率不要太大，一般2e-4左右；训练轮次不要太多，3-5轮就够，多了容易过拟合灾难性遗忘
③ Prompt与RAG应用
Prompt Engineering 提示工程
📄 论文背景

2022年GPT-3论文中发现大模型具备In-Context Learning（上下文学习）能力，不需要微调，只需要给几个示例就能学会任务。随后发展出Zero-Shot、Few-Shot、思维链CoT、自我一致性、ReAct等一系列Prompt技术，是大模型应用成本最低、见效最快的方法。

📚 核心技巧
  • 角色设定：开头明确告诉模型"你是XX领域专家"，效果提升非常明显
  • Few-Shot示例：给3-5个正确示例，比纯文字描述效果好很多
  • 思维链CoT：让模型"一步步思考"，数学/推理任务准确率提升30%以上
  • 输出格式约束：明确要求输出JSON/Markdown格式，避免格式混乱
🚀 实战要点
  • Prompt写得好，效果差几个档次，不要上来就想着微调，先把Prompt优化到极致
  • 复杂任务拆解成多步，比一步让模型出结果准确率高很多
RAG 检索增强生成
📄 论文背景

2020年Facebook在《Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks》中提出RAG，把检索系统和生成模型结合：先从知识库检索相关文档，再把文档作为上下文喂给大模型生成回答。完美解决大模型幻觉、知识过时、私有领域知识问题，是现在企业级大模型落地最主流的方案，成本远低于微调。

📚 理论原理

完整RAG流程：

  1. 文档处理：文档加载→分块（Chunk）→向量化（Embedding）→存入向量数据库
  2. 检索阶段：用户问题向量化→向量数据库相似度检索Top K相关块
  3. 生成阶段：把检索到的上下文和用户问题一起拼入Prompt→大模型基于上下文生成回答
核心优势：不需要微调模型、知识实时更新、答案可溯源、避免幻觉。

💻 核心代码（LangChain极简RAG）
from langchain_community.vectorstores import Chroma
from langchain_community.embeddings import HuggingFaceEmbeddings
from langchain_community.llms import Ollama
from langchain.chains import RetrievalQA

# 初始化
embeddings = HuggingFaceEmbeddings(model_name="BAAI/bge-small-zh-v1.5")
llm = Ollama(model="qwen2:7b")
db = Chroma.from_documents(documents, embeddings, persist_directory="./db")
# 构建RAG链
qa_chain = RetrievalQA.from_chain_type(
    llm=llm, chain_type="stuff", retriever=db.as_retriever(search_kwargs={"k":3})
)
# 问答
print(qa_chain.invoke("公司年假有多少天？"))
🚀 实战要点
  • RAG效果80%取决于分块质量：一般500-1000字一块，块之间重叠20%，不要按固定字符切，要按语义/段落切
  • Embedding模型比大模型本身还重要，中文场景用bge-large-zh或m3e，不要用text-ada-002
  • 进阶优化：查询重写、多路召回（向量+关键词）、重排序（Reranker）、上下文压缩，可以把召回准确率从60%提升到90%以上
④ LLM Agent 智能体
ReAct 推理行动框架
📄 论文背景

2022年《ReAct: Synergizing Reasoning and Acting in Language Models》提出ReAct框架，让大模型交替进行推理（Thought）、行动（Action）、观察（Observation），可以自主调用工具、多步推理完成复杂任务，是现在所有Agent系统的基础范式。

📚 理论原理

ReAct循环：

  1. Thought：模型思考当前状态、需要做什么、需要调用什么工具
  2. Action：输出工具调用指令（搜索、计算、查询数据库等）
  3. Observation：系统执行工具，返回结果给模型
  4. 重复以上步骤，直到模型输出Final Answer完成任务
核心优势：把复杂任务拆解成多步，每一步都可以用工具弥补大模型自身的不足（不会计算、知识过时、无法访问实时数据）。

🚀 实战要点
  • Agent四大核心组件：规划（任务拆解、反思）、记忆（短期对话记忆、长期向量记忆）、工具调用、行动执行
  • 开源框架优先选LangChain或LlamaIndex，复杂工作流用LangGraph做状态机编排，不要自己从头写循环
  • 工程坑点：7B小模型工具调用能力弱，容易出现格式错误、死循环，Agent场景至少用14B以上模型，或者用专门微调的工具调用模型（Qwen2、GLM-4、Gorilla）
⑤ 量化部署与优化
量化技术（GPTQ/AWQ/llama.cpp）
📄 论文背景

大模型默认是FP16精度，10B模型就需要20G显存，很难在消费级显卡和端侧部署。量化就是把模型权重从16位浮点数压缩到4位甚至2位整数，显存占用降低75%以上，精度损失小于1%。主流量化方案：GPTQ（2022）、AWQ（2023）、llama.cpp GGUF（2023）。

📚 理论原理

核心思想：神经网络权重大部分分布在一个很小的区间内，不需要16位精度表示，用更少的bit数就可以近似表示。常用精度对比：

精度显存占用(7B模型)精度损失速度
FP1614GB无1x
INT87GB<0.5%1.5-2x
INT4 (GPTQ/AWQ)3.5-4GB<1%2-3x
INT4 (GGUF Q4_K_M)3.8GB<1%CPU/GPU都能跑

🚀 实战要点
  • N卡部署优先用AWQ量化，速度最快精度最好；A卡/CPU/端侧部署用llama.cpp GGUF格式
  • 7B INT4模型只需要4G显存，甚至可以在手机和嵌入式设备上跑，RTX3090/4090可以流畅跑70B INT4模型
  • 推理加速用vLLM，PagedAttention技术把吞吐量提升10-20倍，支持连续批处理，是现在生产部署标配
KV缓存与推理加速
📄 论文背景

自回归生成时，每个token生成都会重复计算前面所有token的Key和Value，KV缓存就是把已经算过的K/V存起来，避免重复计算，是大模型推理最基础的优化。vLLM提出PagedAttention解决KV缓存内存碎片问题，吞吐量大幅提升。

📚 理论原理

没有KV缓存时，生成第N个token需要重新计算前N个token的注意力，时间复杂度是O(n²)；有KV缓存后，时间复杂度降到O(n)。KV缓存的显存占用：2 * num_layers * num_heads * seq_len * head_dim * 2字节（FP16），长上下文场景KV缓存显存占用会超过模型本身。

🚀 实战要点
  • GQA模型KV缓存显存比MHA小很多，长上下文场景优先选GQA模型
  • 生产环境必须用vLLM/Text Generation Inference，不要用原生HuggingFace Pipeline，吞吐量差10倍以上
  • 本地快速测试用Ollama，一行命令就能跑大模型，自动做量化和优化

📚 精选算法档案

LoRA 低秩适应

大模型微调领域里程碑式工作，让普通开发者也能微调大模型。核心洞察是大模型微调时权重变化是低秩的，只需要训练很小的矩阵就能达到全参数微调效果，几乎不损失精度，没有推理延迟，现在已经是垂直领域微调的标准方案。QLoRA进一步把基座量化到4bit，让7B模型在6G显存上就能微调。

RAG 检索增强生成

企业级大模型落地的首选方案，完美解决大模型幻觉、知识过时、私有数据接入问题。不需要重新训练模型，成本极低，知识可以实时更新，答案可溯源。现在RAG已经从基础版发展出高级RAG（查询重写、多路召回、重排序）和模块化RAG，效果接近微调，成本是微调的几十分之一。

Scaling Law 规模定律

大模型时代的"摩尔定律"，告诉我们为什么模型越大越强，以及如何最优分配计算量和数据量。Chinchilla定律修正了原始Scaling Law，指出参数量和训练token数1:1是最优配比，之前的大模型普遍训练不足。Scaling Law解释了为什么大模型会涌现出小模型没有的能力，是大模型发展的核心理论基础。

🎯 实战案例

企业私有知识库问答系统

技术栈：Qwen2-7B + BGE-large-zh Embedding + BGE-reranker + Chroma向量库 + LangChain

方案选型：优先用RAG而不是微调，数据更新快、成本低、不会出现幻觉。分块策略按语义段落500字一块，重叠100字，用BGE做向量召回Top10，再用Reranker重排序取Top3，准确率可以达到90%以上。

坑点：不要用默认的1000字固定长度分块，语义破碎会严重影响效果；一定要加Reranker，召回准确率提升20%以上；中文场景不要用OpenAI的Embedding，中文效果远不如开源中文Embedding模型。

垂直领域客服大模型

技术栈：Qwen2-14B QLoRA微调 + RAG兜底

方案选型：先收集几万条高质量客服对话数据做SFT微调，让模型学会客服话术和回答风格；再用RAG接入产品知识库和FAQ，解决具体产品问题，两者结合效果最好。QLoRA微调只需要单张4090/3090显卡，训练3个epoch。

坑点：不要用全参数微调，成本高还容易灾难性遗忘；不要只做微调不做RAG，产品更新时需要重新训练，无法实时更新知识；SFT数据质量是关键，一定要用真实客服对话标注，不要用GPT生成的低质量数据。

本地大模型部署

技术栈：Ollama + Qwen2-7B-Instruct vLLM推理

方案选型：个人本地玩直接用Ollama，一行命令启动，自动下载量化模型，支持OpenAI兼容API，非常方便。生产环境部署用vLLM，吞吐量是HuggingFace的10倍以上，支持连续批处理，OpenAI兼容API，可以直接接所有基于OpenAI API开发的应用。

硬件参考：RTX3060 12G可以流畅跑7B INT4；RTX4090 24G可以跑14B INT4/7B FP16；A100 80G可以跑72B INT4/14B FP16。
