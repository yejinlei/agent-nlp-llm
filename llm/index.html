🎯 LLM 是什么

大语言模型（Large Language Model）本质上是一个超级大的N-gram下一词预测模型：给定前面所有的词，预测下一个词是什么。看起来很简单，但当模型参数量和训练数据量达到一定规模时，它会涌现出各种惊人的能力——推理、创作、写代码、工具调用，这就是ChatGPT revolution。

LLM基于Transformer Decoder架构，采用因果自注意力（只能看到前面的词，不能偷看后面），在互联网规模的文本数据上预训练，再经过SFT和RLHF对齐人类偏好。

📏 Scaling Law · 缩放定律

2020年OpenAI在《Scaling Laws for Neural Language Models》中发现一个惊人的规律：模型性能和参数量、数据量、计算量呈幂律关系，只要持续增加这三个因素，性能就能平滑可预测地提升，没有平台期。这是大模型时代最核心的理论基础。

$$L(N) = (N_c/N)^{\alpha_N} \quad \alpha_N \approx 0.076, \quad N_c \approx 8.8 \times 10^{13}$$

更神奇的是能力涌现（Emergence）：当模型规模小于某个阈值时，能力基本为0；一旦突破阈值，能力突然爆发式出现。比如推理能力、数学能力、多步任务能力，都是在百亿参数以上才突然出现的。

🔤 BPE Tokenization · 分词

大模型不直接处理文字，而是把文本切成token（词元）。现在主流的分词算法是BPE（Byte-Pair Encoding）字节对编码：它在字符和词之间找一个平衡，把常见的词作为一个token，罕见的词拆成子词甚至字节，完美解决OOV（未登录词）问题。

🔧 从零实现单头因果自注意力（QKV 是怎么算出来的）

经典实现里，注意力被拆成三个矩阵：Query（我在找什么）、Key（我能提供什么）、Value（我实际贡献什么）。缩放点积注意力的公式只有一行，但每个符号都要落实到代码：

Attention(Q,K,V) = softmax( Q·Kᵀ / √dk ) · V
除以 √dk 是防止点积随维度变大而数值爆炸、把 softmax 推入梯度极小的饱和区。
import torch, torch.nn as nn

class CausalSelfAttention(nn.Module):
    """，seq_len 每步只能看见自己及之前的 token"""
    def __init__(self, d_in, d_out, context_length, dropout, qkv_bias=False):
        super.__init__
        self.d_out = d_out
        self.W_query = nn.Linear(d_in, d_out, bias=qkv_bias)  # 我要找什么
        self.W_key   = nn.Linear(d_in, d_out, bias=qkv_bias)  # 我能给什么
        self.W_value = nn.Linear(d_in, d_out, bias=qkv_bias)  # 我给什么内容
        # 上三角掩码：把"未来"位置置为 -inf，softmax 后概率为 0
        self.register_buffer('mask',
            torch.triu(torch.ones(context_length, context_length), diagonal=1))

    def forward(self, x):              # x: (B, T, d_in)
        b, num_tokens, _ = x.shape
        q, k, v = self.W_query(x), self.W_key(x), self.W_value(x)

        attn_scores = q @ k.transpose(1, 2)                # (B, T, T)
        attn_scores.masked_fill_(self.mask.bool[:num_tokens,:num_tokens], -torch.inf)
        attn_weights = torch.softmax(attn_scores / k.shape[-1]**0.5, dim=-1)
        return attn_weights @ v        # (B, T, d_out)

# 验证：3 个 token，看输出是不是只依赖前面的 token
torch.manual_seed(123)
x = torch.rand(2, 3, 4)
print(CausalSelfAttention(4, 4, 3, 0.0)(x).shape)   # torch.Size([2, 3, 4])

把 W_query/W_key/W_value 换成 多组并行 就叫 多头注意力（MHA）：让模型在不同子空间里同时关注不同的关系（一个头盯语法、一个头盯指代……），最后拼接。现代大模型更进一步改为 GQA——多个 Query 头共享同一组 K/V 头，把推理时的 KV Cache 显存降到 1/4～1/8，这也是 Llama-3、Qwen2 的默认选择。

🧩 GELU：为什么大模型抛弃了 ReLU

里 GPT 的 FFN 层用的是 GELU（高斯误差线性单元） 而不是 ReLU。ReLU 在负半轴直接归零，梯度在 0 处不光滑、容易让神经元"死掉"；GELU 用一个平滑的门控曲线给小负值留一条小通路，梯度更稳、表达更细腻。近似写法：

class GELU(nn.Module):
    """，和官方精确版本数值误差 < 1e-3"""
    def forward(self, x):
        return 0.5 * x * (1.0 + torch.tanh(
            torch.sqrt(torch.tensor(2.0 / torch.pi)) *
            (x + 0.044715 * torch.pow(x, 3))
        ))

class FeedForward(nn.Module):
    """Transformer 块里的 FFN：先升维到 4x，再降回原维度"""
    def __init__(self, cfg):
        super.__init__
        self.layers = nn.Sequential(
            nn.Linear(cfg['emb_dim'], 4 * cfg['emb_dim']),
            GELU,
            nn.Linear(4 * cfg['emb_dim'], cfg['emb_dim']),
        )
    def forward(self, x):
        return self.layers(x)

📐 LayerNorm：为什么不是 BatchNorm？

GPT 在每个子层前用 层归一化（LayerNorm），而不是 CNN 常用的 BatchNorm。区别在于归一化的方向：BatchNorm 是"跨样本、同一特征"归一化（沿 batch 维度），LayerNorm 是"同一样本、跨特征"归一化（沿 feature 维度）。

μ = (1/d)·Σxᵢ　　σ² = (1/d)·Σ(xᵢ−μ)²　　LN(x) = γ · (x−μ)/√(σ²+ε) + β
γ（缩放）和 β（平移）是可学习参数，让网络自己决定"要不要把归一化掰回来"。ε 是防止除零的小常数。

为什么 NLP 偏爱 LayerNorm？因为文本序列长度不一、batch 里样本差异大，BatchNorm 的统计量会剧烈抖动；而 LayerNorm 对每个样本独立计算，天然不受 batch 大小和序列长度影响，训练和推理行为也一致（这点对在线生成至关重要）。

🪟 滑动窗口采样：训练数据是怎么"切"出来的

语言模型训练时，输入和标签是同一段文本错开一位得到的。给定长文本，用一个长度为 max_length 的窗口滑动取样：

def create_dataloader(txt, max_length=4, stride=1):
    """，标签=窗口向右错一位"""
    input_ids = tokenizer.encode(txt)
    for i in range(0, len(input_ids) - max_length, stride):
        yield (input_ids[i : i + max_length],       # 输入
               input_ids[i + 1 : i + max_length + 1]) # 标签(错一位)
stride 的取舍：stride=1 样本最多、覆盖最全，但相邻样本高度重叠（冗余）；stride=max_length 无重叠、样本最少、冗余最低。

📚 第一阶段：预训练 Pre-training

预训练是大模型能力的来源：在互联网规模的文本（数万亿token）上做下一词预测任务，模型学会了语法、常识、逻辑、世界知识。这一步成本极高，70B模型预训练成本在千万美元级别，只有大厂能做。

预训练完成后得到的基座模型（Base Model）能力很强，但它只会"接话茬"，不会听从指令，也不会对话，需要后续对齐。

📉 训练好坏怎么看？—— 交叉熵损失与困惑度

预训练的目标就是"预测下一个词"。模型输出一个全词表概率分布，用 交叉熵损失 衡量它与真实下一个词的差距；再取指数就得到 困惑度（Perplexity, PPL）：

Loss = −(1/N) · Σ log P(wi | w1…wi−1)　　PPL = eLoss
PPL 可以直观理解为"模型在每一步平均在多少个候选词之间犹豫"。PPL = 10 意味着模型大概在 10 个词里做选择。

🎲 生成时的"调味料"：温度与 top-k 采样

同一个模型，换个采样策略，输出的风格天差地别——这正是generate 函数的核心：

🌡️ 温度 Temperature
  • 除以温度后再 softmax
  • T → 0：几乎只选最高概率词，输出死板但稳定
  • T = 1：原始分布
  • T > 1：分布被"压平"，输出更随机更有创意
🎯 top-k 截断
  • 只保留概率最高的 k 个词
  • 其余概率清零，重新归一化
  • 避免从长尾里抽到莫名其妙的怪词
  • k 越小越保守，越大越天马行空
def generate(model, idx, max_new_tokens, context_size, temperature=0.0, top_k=None):
    """，temperature 与 top_k 二选一或组合"""
    for _ in range(max_new_tokens):
        idx_cond = idx[:, -context_size:]                   # 裁到上下文长度
        with torch.no_grad:
            logits = model(idx_cond)[:, -1, :]              # 只取最后一个位置的分布

        if top_k is not None:                               # ① 长尾截断
            top_logits, _ = torch.topk(logits, top_k)
            min_val = top_logits[:, -1].unsqueeze(-1)
            logits = torch.where(logits < min_val, -torch.inf, logits)

        if temperature > 0.0:                               # ② 温度缩放
            logits = logits / temperature
            probs = torch.softmax(logits, dim=-1)
            idx_next = torch.multinomial(probs, num_samples=1)
        else:                                               # ③ 贪心：直接取最大
            idx_next = torch.argmax(logits, dim=-1, keepdim=True)

        idx = torch.cat((idx, idx_next), dim=1)             # 拼回序列，喂给下一步
    return idx

💡 一句话记住：预训练让模型"会接话"，温度控制它"接得多疯"，top-k 控制它"别离谱到外太空"。调 API 时看到的 temperature、top_p 参数，源头就在这里。

🎯 第二阶段：SFT 监督微调

SFT（Supervised Fine-Tuning）是让模型"听懂人话"的第一步：用高质量的"指令-回答"对微调模型，教它按照人类指令输出格式回答问题，而不是继续续写。

SFT数据不需要太多，几万到几十万条高质量指令数据就够了，质量远比数量重要。现在开源社区有大量高质量SFT数据集（Alpaca、ShareGPT、UltraChat等）。

基座模型只会续写。要让它回答问题，得用"指令-回答"数据微调。数据格式有讲究，每个样本是一条结构化的对话：

def instruction_loss(logits, target_ids, response_start):
    # target 里指令部分的标签设为 -100（ignore_index），不参与 loss
    logits = logits[..., :-1, :].flatten(0, 1)
    target = target_ids[..., 1:].flatten
    return torch.nn.functional.cross_entropy(logits, target, ignore_index=-100)

⚖️ 第三阶段：对齐 Alignment

SFT之后模型会回答问题了，但可能会说脏话、输出有害内容、编造事实。对齐就是让模型输出符合人类价值观：有用、诚实、无害。

RLHF 人类反馈强化学习

ChatGPT用的就是RLHF，分三步：

  1. 采样对比数据：对同一个问题，让模型输出多个回答，人工标注哪个更好
  2. 训练奖励模型RM：用标注数据训练一个打分模型，给任意回答打0-1分
  3. PPO强化学习：用奖励模型作为奖励信号，用PPO算法微调大模型，让它输出得分高的回答

DPO 直接偏好优化（2023年新方法）

RLHF太复杂不稳定，DPO绕过了奖励模型和PPO，直接用偏好数据优化大模型，数学上等价于RLHF但实现极其简单，现在开源模型对齐基本都用DPO了。

⚡ LoRA · 低秩适应微调

全参数微调70B模型需要数百GB显存，普通人根本玩不起。2021年微软提出LoRA（Low-Rank Adaptation），冻结原模型所有参数，只在Attention层插入两个小矩阵做低秩分解训练，显存需求降低1000倍，7B模型微调只需要6GB显存，平民也能微调大模型。

$$W' = W + BA, \quad B \in \mathbb{R}^{d \times r}, A \in \mathbb{R}^{r \times k}, r \ll min(d,k)$$

LoRA最巧妙的地方：训练时只更新A和B两个小矩阵，推理时直接把BA加到原W上，没有任何推理延迟，效果和全参数微调差不多。QLoRA进一步把原模型量化到4bit，7B模型甚至4GB显存就能微调。

# LoRA 从零实现核心代码（简化版）
class LoRALayer(nn.Module):
    def __init__(self, base_layer, rank=8, alpha=16):
        super.__init__
        self.base_layer = base_layer
        d, k = base_layer.weight.shape
        self.lora_A = nn.Parameter(torch.randn(rank, k) * 0.01)
        self.lora_B = nn.Parameter(torch.zeros(d, rank))
        self.scale = alpha / rank
        
    def forward(self, x):
        # 原层输出 + LoRA分支
        base_out = self.base_layer(x)
        lora_out = (x @ self.lora_A.T @ self.lora_B.T) * self.scale
        return base_out + lora_out

💬 Prompt 工程

不微调模型，只通过写好提示词就能大幅提升模型效果，这就是Prompt工程。好的Prompt能让模型能力提升几倍。

核心原则

  • 写清楚角色："你是一个有10年经验的资深Python工程师"
  • 给明确任务和约束：不要只说"写个排序算法"，要说"写一个Python快速排序，带注释，处理边界情况，给测试用例"
  • 给出输出格式：要求输出JSON/Markdown/列表，模型会严格遵守
  • Few-Shot给例子：给2-3个输入输出样例，效果远好于纯指令

高级技巧

CoT 思维链

加一句"让我们一步一步思考"，数学推理准确率提升几倍

ToT 思维树

让模型探索多条推理路径，自我评估选择最优

自我一致性

采样多次取多数答案，大幅提升推理准确率

ReAct

让模型交替进行思考和行动（调用工具），Agent基础

🔍 RAG · 检索增强生成

大模型有两个致命问题：知识截止（不知道训练后发生的事）、幻觉（编造事实）。RAG（Retrieval-Augmented Generation）是解决这两个问题最实用的方案：先从外部知识库检索相关文档，把检索到的内容和问题一起喂给大模型，让它基于检索内容回答。

RAG完整工作流

  1. 文档处理：PDF/Word/网页切分成小chunk（通常200-1000字）
  2. 向量化：用Embedding模型把每个chunk转成向量
  3. 存入向量数据库：FAISS/Chroma/Milvus/Pinecone
  4. 检索：用户问题向量化，在向量库召回最相似的Top K个chunk
  5. 生成：把召回的上下文+问题放进Prompt，让大模型基于上下文回答

💻 源码走读 · nanoGPT Causal Self-Attention

nanoGPT是Andrej Karpathy写的最小GPT实现，只有几百行代码，是学习大模型源码的最佳起点：

# Causal Self-Attention 因果自注意力（nanoGPT简化版）
class CausalSelfAttention(nn.Module):
    def __init__(self, n_embd, n_head, block_size):
        super.__init__
        assert n_embd % n_head == 0
        self.n_head = n_head
        # 一次算出Q,K,V
        self.c_attn = nn.Linear(n_embd, 3 * n_embd)
        self.c_proj = nn.Linear(n_embd, n_embd)
        # 因果mask：看不到未来
        self.register_buffer("bias", torch.tril(torch.ones(block_size, block_size))
                                     .view(1, 1, block_size, block_size))

    def forward(self, x):
        B, T, C = x.size
        q, k, v = self.c_attn(x).split(self.n_embd, dim=2)
        k = k.view(B, T, self.n_head, C // self.n_head).transpose(1, 2)
        q = q.view(B, T, self.n_head, C // self.n_head).transpose(1, 2)
        v = v.view(B, T, self.n_head, C // self.n_head).transpose(1, 2)
        # 因果注意力
        att = (q @ k.transpose(-2, -1)) * (1.0 / math.sqrt(k.size(-1)))
        att = att.masked_fill(self.bias[:,:,:T,:T] == 0, float('-inf'))
        att = F.softmax(att, dim=-1)
        y = att @ v
        y = y.transpose(1, 2).contiguous.view(B, T, C)
        return self.c_proj(y)
