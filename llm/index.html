🎯 LLM 是什么

大语言模型（Large Language Model）本质上是一个超级大的N-gram下一词预测模型：给定前面所有的词，预测下一个词是什么。看起来很简单，但当模型参数量和训练数据量达到一定规模时，它会涌现出各种惊人的能力——推理、创作、写代码、工具调用，这就是ChatGPT revolution。

LLM基于Transformer Decoder架构，采用因果自注意力（只能看到前面的词，不能偷看后面），在互联网规模的文本数据上预训练，再经过SFT和RLHF对齐人类偏好。

📏 Scaling Law · 缩放定律

2020年OpenAI在《Scaling Laws for Neural Language Models》中发现一个惊人的规律：模型性能和参数量、数据量、计算量呈幂律关系，只要持续增加这三个因素，性能就能平滑可预测地提升，没有平台期。这是大模型时代最核心的理论基础。

$$L(N) = (N_c/N)^{\alpha_N} \quad \alpha_N \approx 0.076, \quad N_c \approx 8.8 \times 10^{13}$$

更神奇的是能力涌现（Emergence）：当模型规模小于某个阈值时，能力基本为0；一旦突破阈值，能力突然爆发式出现。比如推理能力、数学能力、多步任务能力，都是在百亿参数以上才突然出现的。

🔤 BPE Tokenization · 分词

大模型不直接处理文字，而是把文本切成token（词元）。现在主流的分词算法是BPE（Byte-Pair Encoding）字节对编码：它在字符和词之间找一个平衡，把常见的词作为一个token，罕见的词拆成子词甚至字节，完美解决OOV（未登录词）问题。

🧱 Transformer Decoder · 大模型骨架

所有现代大模型都用Transformer Decoder架构，和NLP里讲的Encoder有几个关键区别：

Transformer Encoder (BERT)
  • ✅ 双向注意力：能看到左右所有词
  • ✅ 适合理解类任务
  • ❌ 不能直接生成文本
Transformer Decoder (GPT)
  • ✅ 因果掩码注意力：只能看到前面的词
  • ✅ 自回归逐词生成文本
  • ✅ 规模越大能力越强

📚 第一阶段：预训练 Pre-training

预训练是大模型能力的来源：在互联网规模的文本（数万亿token）上做下一词预测任务，模型学会了语法、常识、逻辑、世界知识。这一步成本极高，70B模型预训练成本在千万美元级别，只有大厂能做。

预训练完成后得到的基座模型（Base Model）能力很强，但它只会"接话茬"，不会听从指令，也不会对话，需要后续对齐。

🎯 第二阶段：SFT 监督微调

SFT（Supervised Fine-Tuning）是让模型"听懂人话"的第一步：用高质量的"指令-回答"对微调模型，教它按照人类指令输出格式回答问题，而不是继续续写。

SFT数据不需要太多，几万到几十万条高质量指令数据就够了，质量远比数量重要。现在开源社区有大量高质量SFT数据集（Alpaca、ShareGPT、UltraChat等）。

⚖️ 第三阶段：对齐 Alignment

SFT之后模型会回答问题了，但可能会说脏话、输出有害内容、编造事实。对齐就是让模型输出符合人类价值观：有用、诚实、无害。

RLHF 人类反馈强化学习

ChatGPT用的就是RLHF，分三步：

  1. 采样对比数据：对同一个问题，让模型输出多个回答，人工标注哪个更好
  2. 训练奖励模型RM：用标注数据训练一个打分模型，给任意回答打0-1分
  3. PPO强化学习：用奖励模型作为奖励信号，用PPO算法微调大模型，让它输出得分高的回答

DPO 直接偏好优化（2023年新方法）

RLHF太复杂不稳定，DPO绕过了奖励模型和PPO，直接用偏好数据优化大模型，数学上等价于RLHF但实现极其简单，现在开源模型对齐基本都用DPO了。

⚡ LoRA · 低秩适应微调

全参数微调70B模型需要数百GB显存，普通人根本玩不起。2021年微软提出LoRA（Low-Rank Adaptation），冻结原模型所有参数，只在Attention层插入两个小矩阵做低秩分解训练，显存需求降低1000倍，7B模型微调只需要6GB显存，平民也能微调大模型。

$$W' = W + BA, \quad B \in \mathbb{R}^{d \times r}, A \in \mathbb{R}^{r \times k}, r \ll min(d,k)$$

LoRA最巧妙的地方：训练时只更新A和B两个小矩阵，推理时直接把BA加到原W上，没有任何推理延迟，效果和全参数微调差不多。QLoRA进一步把原模型量化到4bit，7B模型甚至4GB显存就能微调。

# LoRA 从零实现核心代码（简化版）
class LoRALayer(nn.Module):
    def __init__(self, base_layer, rank=8, alpha=16):
        super().__init__()
        self.base_layer = base_layer
        d, k = base_layer.weight.shape
        self.lora_A = nn.Parameter(torch.randn(rank, k) * 0.01)
        self.lora_B = nn.Parameter(torch.zeros(d, rank))
        self.scale = alpha / rank
        
    def forward(self, x):
        # 原层输出 + LoRA分支
        base_out = self.base_layer(x)
        lora_out = (x @ self.lora_A.T @ self.lora_B.T) * self.scale
        return base_out + lora_out

💬 Prompt 工程

不微调模型，只通过写好提示词就能大幅提升模型效果，这就是Prompt工程。好的Prompt能让模型能力提升几倍。

核心原则

  • 写清楚角色："你是一个有10年经验的资深Python工程师"
  • 给明确任务和约束：不要只说"写个排序算法"，要说"写一个Python快速排序，带注释，处理边界情况，给测试用例"
  • 给出输出格式：要求输出JSON/Markdown/列表，模型会严格遵守
  • Few-Shot给例子：给2-3个输入输出样例，效果远好于纯指令

高级技巧

CoT 思维链

加一句"让我们一步一步思考"，数学推理准确率提升几倍

ToT 思维树

让模型探索多条推理路径，自我评估选择最优

自我一致性

采样多次取多数答案，大幅提升推理准确率

ReAct

让模型交替进行思考和行动（调用工具），Agent基础

🔍 RAG · 检索增强生成

大模型有两个致命问题：知识截止（不知道训练后发生的事）、幻觉（编造事实）。RAG（Retrieval-Augmented Generation）是解决这两个问题最实用的方案：先从外部知识库检索相关文档，把检索到的内容和问题一起喂给大模型，让它基于检索内容回答。

RAG完整工作流

  1. 文档处理：PDF/Word/网页切分成小chunk（通常200-1000字）
  2. 向量化：用Embedding模型把每个chunk转成向量
  3. 存入向量数据库：FAISS/Chroma/Milvus/Pinecone
  4. 检索：用户问题向量化，在向量库召回最相似的Top K个chunk
  5. 生成：把召回的上下文+问题放进Prompt，让大模型基于上下文回答
# 最简RAG示例（LangChain + Chroma + Qwen2）
from langchain.vectorstores import Chroma
from langchain.embeddings import HuggingFaceEmbeddings
from langchain.llms import Ollama
from langchain.chains import RetrievalQA

# 加载向量库
embeddings = HuggingFaceEmbeddings(model_name="bge-small-zh")
db = Chroma(persist_directory="./db", embedding_function=embeddings)

# RAG链
llm = Ollama(model="qwen2:7b")
qa_chain = RetrievalQA.from_chain_type(
    llm=llm, chain_type="stuff",
    retriever=db.as_retriever(search_kwargs={"k": 3})
)
result = qa_chain.run("公司年假有多少天？")

🤖 LLM Agent · 智能体

光靠RAG只能查资料，Agent让大模型能自主规划、使用工具、完成复杂任务：比如自动上网查资料、写代码执行、调用计算器、发邮件、操作软件。这是当前最火的方向。

Agent四大核心组件

  • 规划 Planning：把大任务拆成小步骤，遇到错误反思调整（ReAct、Reflexion）
  • 记忆 Memory：短期记忆（上下文窗口）、长期记忆（向量数据库）
  • 工具调用 Tool Use：调用搜索引擎、代码解释器、API、数据库等
  • 行动 Action：执行工具调用，获取结果继续下一步

📦 量化与部署

大模型默认用FP16精度，7B模型就要14GB显存，根本没法在普通电脑跑。量化就是降低权重精度（FP16→INT8→INT4），大幅降低显存需求和推理速度，精度损失很小。

量化技术对比

量化方案精度7B显存需求精度损失速度
FP16 半精度16bit14GB无基准
INT8 量化8bit7GB极小1.5-2倍
GPTQ/AWQ4bit3.5-4GB很小3-4倍
GGUF (llama.cpp)4bit3.5-4GB很小CPU也能跑

💻 源码走读 · nanoGPT Causal Self-Attention

nanoGPT是Andrej Karpathy写的最小GPT实现，只有几百行代码，是学习大模型源码的最佳起点：

# Causal Self-Attention 因果自注意力（nanoGPT简化版）
class CausalSelfAttention(nn.Module):
    def __init__(self, n_embd, n_head, block_size):
        super().__init__()
        assert n_embd % n_head == 0
        self.n_head = n_head
        # 一次算出Q,K,V
        self.c_attn = nn.Linear(n_embd, 3 * n_embd)
        self.c_proj = nn.Linear(n_embd, n_embd)
        # 因果mask：看不到未来
        self.register_buffer("bias", torch.tril(torch.ones(block_size, block_size))
                                     .view(1, 1, block_size, block_size))

    def forward(self, x):
        B, T, C = x.size()
        q, k, v = self.c_attn(x).split(self.n_embd, dim=2)
        k = k.view(B, T, self.n_head, C // self.n_head).transpose(1, 2)
        q = q.view(B, T, self.n_head, C // self.n_head).transpose(1, 2)
        v = v.view(B, T, self.n_head, C // self.n_head).transpose(1, 2)
        # 因果注意力
        att = (q @ k.transpose(-2, -1)) * (1.0 / math.sqrt(k.size(-1)))
        att = att.masked_fill(self.bias[:,:,:T,:T] == 0, float('-inf'))
        att = F.softmax(att, dim=-1)
        y = att @ v
        y = y.transpose(1, 2).contiguous().view(B, T, C)
        return self.c_proj(y)
